## 2. EXISTING

- **Detector.** `triage._classify` assigns each page exactly one `PageKind`: `blank`, `broken_text`, `scanned`, `vector_text`, `hybrid` or `digital`. The order is fixed in code (blank, then broken_text, then the text-empty branch scanned, vector_text, scanned-by-hybrid-image, then hybrid, then digital). `broken_text` requires `n_chars >= MIN_CHARS_PER_PAGE`; `scanned` and `vector_text` require `n_chars < MIN_CHARS_PER_PAGE`; so those two never coincide.
- **Route.** `NEEDS_OCR = {scanned, broken_text, vector_text, hybrid}`; everything else uses the text layer. `arpipe/CLAUDE.md` states it per class: digital "read it, free"; scanned "OCR"; hybrid "read text, OCR the image"; broken-text "OCR, discard the text layer"; vector-text "OCR". The routing configuration (`default.yaml`) has thresholds only, no class-to-route table.
- **Legacy-font / remap behavior.** None in production. There is no `legacy_font` `PageKind`, no remap code path, and no remap route in `arpipe/`. `verify._window_is_legacy_font` is a wrong-language quarantine heuristic run on extracted MD&A text, not a page router. The corpus freeze explicitly excluded remapping (`freeze_protocol.md`). T0.4 defines a REMAP lane in prose only (`tools/t0_4/` is setup-only, no dispatch).
- **T0.4 benchmark record.** Frozen configs, 475-unit Track-A manifest (FIT 223, VALIDATION 118, HOLDOUT 134), 208-record Track-B manifest, `NOT_YET_RENDERED` image hashes, a fixed renderer contract (RGB PNG, 300 DPI, no preprocessing), and a frozen `gold_schema.json` with `NOT_YET_ANNOTATED` sentinels.
- **Existing reference conventions** (`configs/eval_protocol.md`, `arpipe/labeller.py`, `arpipe/models.MDASpan`): 0-based inclusive physical page numbers; reason code `NO_MDA_IN_DOC` as the registered absence state; `verified_by="read_pdf"` mandatory for scored gold; holdout documents may be labelled blind but must not be inspected to tune.
- **Existing annotation tooling.** `arpipe label` is a document-level MD&A start/end labeller. A search of tracked files for annotation, label, gold and oracle names finds no page-level, region, reading-order, factual-field or route annotation tool.
- **Frozen blinded annotation roster.** `dataset/corpus_freeze/annotation_roster.csv` (`23d6228`) lists 25 documents, all `FIT` with local PDFs and all inside the Track-B universe (`annotation_roster ⊆ development ⊆ FIT` per `freeze_protocol.md`). Its gold columns are blank for every row (0 filled cells). The columns are `mda_present`, `mda_start_page`, `mda_end_page`, `heading_text_verbatim`, `heading_form`, `boundary_ambiguous`, `ambiguity_reason`, `excluded_neighbours`, `language`, `per_page_text_quality`, `annotator_id`, `annotation_date`, `minutes_spent`, `saw_pipeline_output`. It has a single `annotator_id` column and no double-annotation or adjudication design. It is a 25-document subset, not the T0.4 Track-B universe of 194 profiled documents.

## 5. Critical checks

### 5.1 Five-class to three-route mapping

The five routing classes are those in `metrics_spec.json` (`ROUTING.classes`). They are **not** the production page classes: CLAUDE.md's five are digital, scanned, hybrid, broken-text, vector-text. T0.4 dropped `hybrid`, added `legacy_font`, and renamed digital to `native_ok`.

Why `legacy_font` is unresolved:

1. The frozen detector has no `legacy_font` class and produces none. Within the frozen record it exists only as the manifest label `legacy_font_candidate`.
2. That label is built from `cid_or_broken_text_indicator` (`core.py:318`), and the frozen corpus defines that indicator as `p["kind"] == "broken_text"` (`freeze_extraction_corpus.py:975`). Measured: all **803 of 803** `broken_text` pages in `page_profile.csv` carry it, and no page of any other kind does. In the 475-unit manifest the label and the representation class `broken_text` coincide on **20 of 20** units, and neither appears without the other. The frozen corpus itself calls it "classic legacy/CID-font symptom" and marks it `INFERRED`.
3. So `legacy_font` and `broken_text` are the same physical pages, and the frozen detector routes those pages to `OCR`. The route `LEGACY` and the REMAP lane are registered in T0.4 prose only. No frozen artifact says that `legacy_font` maps to `LEGACY`, or that the `LEGACY` label equals the REMAP lane. The preregistration's "native+remap+routed-OCR" pipeline is suggestive but is naming, which the task forbids as evidence.

Two further detector kinds occur in the frozen data but are outside the five registered classes: `hybrid` (102 of 475 units; production route is "read text, OCR the image", which is neither `NATIVE` nor `OCR`) and `blank` (55 units; no route stated). They do not affect the literal oracle subset (section 5.3) but would affect the stratum reading.

**Result: `ORACLE_ROUTE_MAPPING_UNRESOLVED`. `configs/t0_4_gold/oracle_route_mapping.json` was not created.**

### 5.4 Oracle universe facts that are resolved

- **HOLDOUT eligibility is explicit.** `oracle_routing_spec.json` says "from the frozen FIT and VALIDATION partitions only", and the preregistration repeats "selected from frozen FIT/VALIDATION units". Oracle `HOLDOUT_count = 0` under either reading. `ORACLE_HOLDOUT_ELIGIBILITY_UNRESOLVED` does not apply.
- **Double-annotation slice is underspecified** (B4 below). The rule "every unit whose deterministic SHA-256 rank begins with hexadecimal 0, 1, 2, or 3", expected fraction 0.25, names no seed, key or encoding. The only SHA-256 rank in the frozen record is the manifest's `selection_rank`, which is the sampling rank. Selected units are by construction the minimum-rank page of their cell, so that rank is heavily biased toward small first digits. Across all 475 units, 249 begin with `0`, and 355 (74.7%) begin with 0 to 3. Within the 79 literal-reading units, 50 (63.3%) do. Using it would double-annotate roughly two thirds of the subset, contradicting the frozen `expected_fraction` of 0.25. A different rank needs a new seed and encoding, which is a new frozen decision, not a preserved rule.
