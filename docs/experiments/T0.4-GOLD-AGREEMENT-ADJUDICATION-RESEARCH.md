## Principle: independent records first, adjudication second

Independent annotations are evidence about reproducibility of the protocol. An adjudicated record is evidence about the final reference decision. They are different data products and must never overwrite each other. S02 defines reliability around observers applying common instructions independently; S06–S07 caution that pre-existing labels or model output can anchor human judgements. S01 further supports selecting a measure for the actual annotation unit rather than treating one coefficient as universal.

For every eventual double-annotated unit, retain:

```text
raw_annotation_A + raw_annotation_B
    -> task-specific agreement measures and disagreement taxonomy
    -> adjudication record (if triggered)
    -> ADJUDICATED_REFERENCE_ANNOTATION or explicit unresolved ambiguity
```

The arrow is append-only. It is not an overwrite.

## B6: double-annotation design

### Frozen rule that must not be overgeneralized

`oracle_routing_spec.json` fixes double annotation for every preselected OracleRouteGold FIT/VALIDATION coverage unit whose deterministic SHA-256 rank begins `0`, `1`, `2`, or `3`, with expected 25% selection and a third human adjudicator when routes differ or confidence is not high. This worktree's frozen-manifest analysis found that `selection_rank` itself is strongly minimum-rank biased (74.74% of all Track-A selected pages begin `0`–`3`), so it is unsuitable as a generic overlap selector. The existing Oracle rule uses a separate SHA-256 rank; a future Page/Document selector must likewise use an independent, precommitted seed and population.

### Alternatives for PageGold and DocumentGold

| Design | Statistical usefulness | Rare-condition protection | Burden / bias risk | Reproducibility | Finding |
|---|---|---|---|---|---|
| Simple random overlap | estimates population-average agreement if the population/seed are fixed | weak for sparse cells | low burden; can miss rare/corner cases | high | insufficient by itself |
| Proportional stratified overlap | supports stratum estimates where counts permit | better but rare cells can remain empty | more complex; no automatic guarantee | high | useful component |
| Fixed count per stratum | visibly covers each observed cell | strong only when cells have ≥2 eligible units | over-represents rare cells in pooled estimate | high | diagnostic, not a population estimate |
| Targeted difficult-case overlap | stress-tests known ambiguity/layout risks | strong | biased if pooled with random reliability estimate | high if rules are frozen | keep separate from random estimate |
| Hybrid random plus minimum-cell diagnostic layer | reports a population estimate and a rare-case diagnostic separately | strong and transparent | workload is adjustable, but more bookkeeping | high | **recommended design class** |

The hybrid design is a recommendation, not a selected percentage. First define the exact final annotation population and any exclusion/ambiguity policy. Then, before assignments, freeze: the population manifest hash; an independent secret/public-after-lock seed; inclusion variables; the random-overlap rate or size; the diagnostic cell rule; selection hashes; assigned annotator; and the report strata. Do not select cases after seeing disagreement. Random and targeted layers must be reported separately rather than pooled.

The frozen burden analysis illustrates why a rate cannot be casually chosen: 20 double-annotated units observed at 80% exact agreement have a Wilson 95% interval of approximately 0.584–0.919, whereas 100 units at 90% have approximately 0.826–0.945. It also shows that a 25% random slice has a 56.25% chance of missing a condition represented by only two documents. These are design illustrations, not an ARPipe power calculation and not a prescribed sample size.

### Fields that need independent annotation

| Product / field group | Independent double annotation? | Reason |
|---|---|---|
| Page reference text and text-status | Yes on the formal reliability layer | CER depends directly on human transcription; error cannot be diagnosed from adjudicated text alone |
| Reading-order anchors and eligible pair directions | Yes on formal layer | anchor granularity and multi-column order are protocol-sensitive |
| Heading detection/text/level where a heading metric is retained | Yes on field's declared layer | separates matching/level ambiguity from engine evaluation |
| Factual field occurrence and values where the factual metric is retained | Yes on field's declared layer | exposes alignment and normalization disagreement |
| Document presence, candidates, start/end, ambiguity and neighbours | Yes on the formal reliability layer | drives the Track-B primary endpoint and denominator handling |
| Oracle route | Already frozen for 25% of its defined subset | frozen rule applies exactly as written |
| Operational/provenance fields generated by server | No human duplicate required | they should be mechanically validated rather than independently re-entered |

All remaining units may be singly annotated only after training, pilot, and the formal reliability protocol have been frozen. This is not a licence to report a single-annotator final reference as human agreement.

## Training → pilot → formal reliability → final Gold

| Phase | Permitted activity | Rule status | May annotators discuss? | Output |
|---|---|---|---|---|
| Training | synthetic/non-Gold examples, tool familiarisation | draft | yes | no Gold; teaching notes |
| Pilot / calibration | predeclared non-Gold or explicitly segregated pilot material | may change, versioned | yes after independent first pass | issue log, revised draft guideline |
| Formal reliability | selected final-population units only after protocol freeze | immutable for that version | no until independent records close | raw paired records, agreement report |
| Final Gold | all assigned units under the same frozen version | immutable | no cross-annotator access | raw and, where necessary, adjudicated reference |

After formal reliability begins, a disagreement may trigger an adjudication but not a rule change targeted to that unit. A genuinely needed change produces a new protocol version, rationale, affected-unit list, timestamp, impact statement, and a separate calibration/reliability cycle; it must not be silently blended into an existing agreement denominator.

## Annotation independence and leakage controls

Each annotator receives a stable anonymous identifier and a separate authenticated session. Before independent submission, the interface must enforce: no other annotator's payload/comment; no adjudicator record; no engine/OCR/ARPipe output; no route/benchmark condition; no split/stratum/issuer indicator; no revealing filename/path/task name; and no mutable prefilled prediction. Use opaque document/task IDs. The custom POC shows an isolation pattern but deliberately has no authentication; it is a feasibility result, not a security control. Label Studio Community's POC made annotations visible between users, so it is not adequate for blind independent work without an external isolation design.

Visually observable facts (e.g., a scan, two columns, Devanagari, page appearance, or approximate document length) cannot be hidden and must be recorded as `UNAVOIDABLE_SOURCE_INFORMATION`. Metadata that reveals why a unit was sampled is `PREVENTABLE_PROTOCOL_LEAKAGE` and must be stripped.

## Agreement matrix

Agreement is computed from raw independent records only. A final report gives numerator, denominator, point estimate, interval method, cluster/unit count, missingness, and the precise comparison/alignment rule.

| Annotation task | Unit | Raw agreement measure | Why appropriate | Assumptions / limitations | CI and reporting |
|---|---|---|---|---|---|
| MD&A presence state | document | exact agreement plus nominal Krippendorff alpha if state distribution supports it | categorical state with possible missing records | alpha is prevalence-sensitive; do not use it alone or apply generic “good” cut-offs | paired count, confusion table, bootstrap CI; report unscorable input separately |
| MD&A start page | documents with both asserted spans | exact start; ±1 start; signed and absolute page distance | page boundary has ordered error magnitude | ±1 is diagnostic, not a substitute for exact endpoint | distribution/quantiles and cluster bootstrap interval for exact/±1 rate |
| MD&A end page | documents with both asserted spans | exact end; ±1 end; signed and absolute page distance | captures mixed-page/hierarchy errors | same as start | same as start |
| MD&A full page span | paired asserted spans | span IoU plus exact-span rate | directly describes overlap of page intervals | no conclusion for unresolved/missing state; retain those counts | IoU distribution, median/quantiles, bootstrap interval, both-span denominator |
| Heading inventory | matched page headings | precision/recall/F1 under a frozen text/geometry matching rule | set-valued detection task | matching rule changes the result; level is separate | TP/FP/FN, micro/macro scope, document-cluster bootstrap |
| Heading level | matched headings | exact level agreement; ordinal alpha only if levels have a stable ordinal definition | distinguishes detection from hierarchy label | hierarchy varies by document; report unmatched headings separately | matched-heading count and bootstrap interval |
| Reading order | common eligible directed anchor pairs | pair-direction agreement; relation F1 if anchor sets differ | same relation form as frozen system metric | only comparable anchors/pairs count; ties/exclusions explicit | pair count, page/document cluster bootstrap; supplementary sequence score only for complete sequences |
| Factual fields | frozen aligned fact occurrences | occurrence precision/recall/F1; raw-string exact; normalized-value exact per field type | mix of set detection and values | numeric normalisation/equivalence must precede annotation; avoid a single alpha for a set | alignment rule, TP/FP/FN, value denominator, cluster bootstrap |
| Transcription | page | exact string rate and symmetric normalized edit distance; report raw character count | directly quantifies independent visible transcription difference | needs a predeclared treatment for whitespace, unreadable marks, tables, and empty pages | page and document counts; document-cluster bootstrap; do not call one annotator “truth” |

S04–S05 are transferable segmentation evidence: boundary metrics have non-obvious properties and near misses deserve an explicit representation. Accordingly, ARPipe should report exact and tolerance/distance/span perspectives together. The frozen system endpoint remains page-span IoU; the matrix above is for **human agreement**, not a replacement for the system metric.

## Uncertainty and reporting

S03 supports bootstrap intervals for agreement statistics and cautions against relying on point estimates or universal coefficient cut-offs. For an eventual formal reliability report:

1. Use a two-sided 95% nonparametric bootstrap that resamples at the document cluster for page-level material; use issuer-cluster resampling only when the declared reliability sample and cluster count make that choice meaningful. Freeze the rule before results.
2. Report raw numerator/denominator first. Then give the estimate, percentile interval, number of resamples/seed, independent unit and cluster count, missing records, and every eligibility exclusion.
3. For page boundaries, report the full/summary distribution of signed and absolute distances and span IoU, not just a mean. For reading order, report eligible relation count and anchor-matching/exclusion counts.
4. Mark strata with insufficient independent clusters `NOT_ESTIMABLE`; do not fabricate precision from a small rare cell.
5. Do not set a pass/fail reliability threshold in this research worktree. A later author-approved protocol may define decision criteria, but should retain estimates and intervals rather than only a threshold label.

## Adjudication model comparison

| Model | Reproducibility / workload | Fit for ARPipe boundary ambiguity | Recommendation |
|---|---|---|---|
| Majority vote | cheap for categorical triples | masks reasons and cannot resolve source ambiguity | not sufficient as the final mechanism |
| Annotator discussion then consensus | can improve training | contaminates independent agreement and can mask minority evidence | training/pilot only, before formal reliability |
| Single expert adjudicator | practical, fast, permits structural expertise | needs documented reason and escalation for uncertainty | recommended first review stage |
| Panel | broader expertise | high cost; consensus can still hide ambiguity | reserve for escalated policy cases |
| Hierarchical review | transparent escalation | more process overhead | recommended: expert review → protocol-owner/panel only for rule/source ambiguity |
| “Adjudicate every disagreement to one exact span” | superficially simple | scientifically wrong for genuine ambiguity/multiple valid spans | prohibited |

Recommended trigger: any raw disagreement, any low confidence, an ambiguity/missing-evidence flag, an invalid/contradictory record, or a predeclared high-risk boundary category. The adjudicator sees source evidence, the written protocol, and the completed raw records with annotator identity pseudonymised; it never sees engine output or benchmark results. It writes: outcome; agreement/disagreement type; admissible alternatives; source/guideline/technical ambiguity state; evidence/reason; protocol version; and escalation need. Consensus means independent records happen to agree. An adjudicated reference means an authorized review created a final record; neither is a reliability statistic.
