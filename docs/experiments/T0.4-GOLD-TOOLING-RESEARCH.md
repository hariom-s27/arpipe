# T0.4 Gold Tooling Research

**Status:** RESEARCH_ONLY / `TOOLING_POC_ONLY`. No corpus document, Gold record, human annotation, OCR engine, or benchmark was used.
**Sources:** S09–S13 in [`research_source_register.csv`](../../research_source_register.csv).
**Question:** which approach can meet ARPipe's evidence, context, blinding, provenance, and 100–600 page constraints with the fewest unresolved methodological compromises?

## Requirements that matter for ARPipe

The required tool is not merely a box-drawing UI. It needs a page-image workflow for image-only PageGold, whole-document navigation for DocumentGold, physical-page indexing, typed headings/facts/order anchors, two independent annotators, a separation between independent work and adjudication, durable raw/adjudicated provenance, local/private operation, and export that preserves source hashes and semantic conventions. The tool must also make preventable metadata leakage auditable.

`SUPPORTED` below means the listed source/POC established the capability for the stated version/condition. `PARTIALLY_SUPPORTED` means a material constraint remains. `REQUIRES_CUSTOMIZATION` means a feature can plausibly be built around the tool but is not demonstrated as an ARPipe-ready workflow. `UNKNOWN` is deliberately not converted to “no.”

## Shortlist and practical risks

**Conditional shortlist:**

1. **Hardened custom local/private interface** for the exact ARPipe package, if the author can support credentialed roles, independent assignment, append-only raw records, PDF/image hashing, backup, audit logging, and a small real-but-non-Gold usability/security pilot. It best matches full-document navigation, page-local evidence, blinding, adjudication, and provenance—but the POC is deliberately too weak to call it deployment-ready.
2. **Label Studio Community plus an external controlled workflow** if its convenience is worth the preprocessing/provenance engineering and the project can technically prevent peer visibility (for example, separate assignments/projects plus a controlled adjudicator import) and revalidate it after every upgrade. It demonstrated viable long image-list navigation, not blind annotation.
3. **Prodigy with a custom interface** only after license, 100–600 page workflow, PDF/image handling, isolation, and export POC. Its documented review/annotator metadata makes it plausible; no ARPipe feasibility evidence was collected here.

**Not shortlisted without material new evidence:** doccano. Its documented core is collaborative text labeling, and neither a native page-image/coordinate workflow nor a compatible local runtime was demonstrated. This does not assert that an extension is impossible; it says that choosing it today would require untested customization.

### Open questions for a later, separate POC

- Can the selected production deployment authenticate annotators and adjudicators with least-privilege roles, including direct API access—not just the UI?
- Is an immutable, versioned external assignment/provenance ledger accepted as the source of hashes, task version, and blinding record?
- Does 300-DPI realistic annual-report imagery remain usable at 100–600 pages with the chosen cache, storage, and network policy?
- How are corrections represented without overwriting raw records?
- Can documents be assigned by opaque task ID without filename, issuer, split, stratum, or engine leakage?
- Can a formal formal-reliability selector remain hidden from annotators while preserving reproducible assignment logs?

## Author decision needed

The author should choose a *deployment path*, not a feature-matrix score: (a) fund/harden the custom interface; (b) engineer and re-test a controlled Label Studio workflow; or (c) conduct a licensed Prodigy POC. Selection must occur after the final Gold field/schema, B6 overlap, B7 anchor, and access-control requirements are frozen. No tool has been selected in this worktree.
