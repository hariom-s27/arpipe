## 1. `vector_text` route

**Registered route: `vector_text → OCR`.**

Source: `arpipe/triage.py` — `PageKind.VECTOR_TEXT` is a member of `NEEDS_OCR`, and `ocr_page_numbers` returns every page whose kind is in that set. The page kind is defined in `arpipe/models.py` and assigned when a page has fewer than the minimum text characters, is not dominated by an image, and has at least `VECTOR_PATH_TEXT_THRESHOLD` drawing paths.

Frozen rationale, quoted from the frozen sources: "glyphs drawn as vector paths -> OCR" (`arpipe/models.py`), "letters drawn as shapes -> OCR" (`arpipe/CLAUDE.md`), "many tiny fill-paths + no text => vector text" (`arpipe/triage.py`). The page has almost no encoded text but many vector drawings, so there is no usable text layer and the page must be recovered from its rendered image.

| Layer | Artifact | Stance |
|---|---|---|
| Text-layer detector definition | `arpipe/models.py`, `arpipe/triage.py` | Explicit: OCR |
| Routing configuration | `arpipe/configs/default.yaml` | Detection threshold only (`triage.vector_path_text_threshold`); no page-class-to-route table, the route is code-defined by `NEEDS_OCR` |
| T0.4 preregistration | this protocol | Class listed at `b937b58` without a route; explicit OCR after this closure (see below) |
| T0.4 benchmark configuration | `metrics_spec.json`, `oracle_routing_spec.json`, `sampling_spec.json` | `vector_text` is a routing class, an oracle-subset label, and a sampling stratum; no route mapping; the gold route vocabulary contains `OCR` |
| Future execution harness | `tools/t0_4/` | Setup only; no routing dispatch |

All representations agree and none contradicts the detector. At `b937b58` this check returned UNRESOLVED at the T0.4 design layer: the detector defined the route but T0.4 never restated it. The preregistration now records it by citation. That clarification introduces no new route, changes no configuration, and pre-assigns no ORACLE_ROUTING label. "OCR" here is the page-level routing decision; the production pipeline runs OCR lazily (locate first, then OCR only what it needs), which is separate from the route.

## 2. Observed-cell definition

An observed cell is an `(issuer_id, sampling_stratum, era, representation_class, length_category)` combination that occurs on at least one profiled physical page of the frozen corpus metadata. Physical page identity is `(document_id, page_number)`; overlapping condition labels never create a second unit.

## 3. Zero-availability-cell definition

A zero-availability cell is a combination in the Cartesian product of the declared category levels that contains zero physical pages. It is never called observed and is never filled, padded, or duplicated. Declared levels: 36 issuers (`issuer_split.csv`) × 11 sampling strata (`sampling_spec.json`) × 2 eras × 3 length categories (manifest-schema enums) × 7 representation classes (the six detector page kinds mapped by the frozen builder, plus its `other` fallback) = 16,632 cells.

## 4. Observed cell count

**475** observed cells, split across issuer-disjoint partitions as FIT 223, VALIDATION 118, HOLDOUT 134.

## 5. Zero-availability cell count

**16,157** zero-availability cells (16,632 declared − 475 observed). The set is fixed by the declared levels and the corpus, and is pinned in the record by `zero_availability_cells_sha256`. Declared levels with no observed page anywhere: strata `broken_text` and `ocr_layer_proxy` (no page has either as its highest-priority label), and representation class `other`. This is a property of the corpus and priority order, not a sampling defect.

## 8. Semantic treatment of "unobserved" / "unseen"

"Unobserved" occurs twice, in `sampling_spec.json` (`shortfall_policy`) and in the preregistration's sampling paragraph. Both are coverage terminology: a cell with no page in the frozen corpus metadata, that is, a zero-availability cell. Both are retained unchanged. "Unseen" does not occur in any scoped file. Neither word is used for a split or evaluation role, and neither was rewritten to resemble evaluation vocabulary.

## 9. Terminology corrections

Before: "Paired engine estimates retain honest held-out evaluation; sparse cells may be descriptive or `NOT_ESTIMABLE`." ## Observations outside the four checks (not acted on)

Both would be redesign rather than closure, so neither was changed.

1. `oracle_routing_spec.json` lists `native_clean_control` among the `condition_labels` that select oracle-annotation units, but it is a sampling stratum and no unit carries it as a label. Read literally, the subset is 79 of 341 FIT and VALIDATION units and excludes all 42 native-control units; read as a stratum it would be 121. Decide which reading is intended before oracle annotation.
2. The routing metrics use five classes, while oracle labels use three routes (`NATIVE`, `LEGACY`, `OCR`). Per-class precision, recall, and the confusion matrix need a class-to-route map that T0.4 states only for `vector_text`. `broken_text` is an OCR class in the detector, while the frozen corpus calls it the legacy-font symptom and T0.4 defines a separate REMAP lane; the gold-phase protocol should settle this.
