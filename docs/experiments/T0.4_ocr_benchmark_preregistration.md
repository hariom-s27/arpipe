# T0.4 OCR/document-recovery benchmark preregistration

Status: setup and preregistration only. No benchmark result has been observed or generated. This document and the machine-readable configuration are frozen before execution.

## Research question and scope

ARPipe asks whether the correct Management Discussion & Analysis span can be obtained reliably from annual-report PDFs. OCR quality matters, but it is not the document-level research outcome. T0.4 therefore registers two linked experiments with different units and gold data:

| Property | Track A — page recovery | Track B — ARPipe document task |
|---|---|---|
| Unit | `(document_id, page_number) × engine` | `document_id × engine-route × common downstream pipeline` |
| Evidence available | One immutable rendered page image | Complete document through the registered ARPipe stages |
| Gold | PageGold transcription, facts, headings, regions, and reading-order pairs | DocumentGold MD&A presence and section boundaries |
| Primary endpoint | CER | Page-span IoU |
| Prohibited inference | MD&A end-page localization from an isolated page | Engine-specific downstream pipeline |

The shared link is `EngineRawOutput → CommonARPipeRepresentation`. Track A evaluates recovery from the page image. Track B evaluates how that recovery affects MD&A localization when every engine feeds the same downstream implementation.

## Frozen history and inputs

The base is `ff030d97c13c8a2a977521bf91be2aca0cbf3034` (T0.3A-R1). T0, T0.1R, T0.2, T0.3A, and T0.3A-R1 artifacts are protected. Corpus policy remains `NO_ACQUISITION`.

The deterministic builder derives all counts from the frozen corpus. It predeclares every historical record; records with no profiled/local PDF input are retained as `INPUT_UNAVAILABLE`, never silently dropped. Missing-byte records that were deliberately excluded from all frozen partitions remain `UNASSIGNED_HISTORICAL`; no split is invented for them. Every assigned record uses the existing issuer-disjoint FIT, VALIDATION, and HOLDOUT assignment, and no document or issuer is moved.

Existing proxy labels keep their evidence level. Detector output is `CANDIDATE_PROXY`; fiscal-year/split metadata is `VALIDATED_METADATA`; absent human gold is `NOT_YET_ANNOTATED`.

## Primary engines and capability asymmetry

The primary comparison contains exactly:

1. Tesseract 5 with English and Hindi data — local OCR baseline.
2. PaddleOCR-VL 1.6 — local/open document-parsing system.
3. Surya 2 — local/open OCR and document-analysis system.
4. Gemini 2.5 Flash-Lite — cloud visual/document-understanding comparator.

They do not expose identical structure, confidence, or table capabilities. Unsupported fields are `NOT_AVAILABLE`; they are not failures and are never synthesized. Exact runtime versions, checkpoints/hashes, Python/CUDA versions, and hardware are execution-time provenance requirements. T0.4 does not install or probe engines.

AWS Textract is registered only as a future optional commercial-reference extension point. Google Document AI and Azure Document Intelligence are named future extension points. None is part of the primary comparison or executed here.

## Track-A input fairness

Every selected page follows one immutable path:

`PDF page → fixed ARPipe renderer → RGB PNG at 300 DPI → no additional preprocessing → SHA-256 content address → same bytes to all four engines`.

The engine interface receives only the PNG, image hash, page number, and opaque document identifier. It fails closed if passed an original PDF, neighboring/previous/following page, document text, hidden PDF text, bookmarks, TOC, external semantic metadata, prior engine output, or page context. It also fails if primary-engine image hashes differ or an adapter silently falls back to another engine.

Native-PDF or document-context capabilities require a separately registered future experiment and cannot be mixed with Track A.

## Sampling and benchmark manifest

Sampling strata and analytical condition labels are separate. Each physical page occurs once under key `(document_id, page_number)`, receives one deterministic primary `sampling_stratum`, and may carry multiple sorted `condition_labels`. A multi-column, scanned, pre-2015 table candidate therefore remains one page with four labels—not four pseudo-observations.

P-X1's fixed target of 20 pages per stratum had no scientific sample-size derivation and allowed document split exceptions. T0.4 uses a pre-result coverage rule: within every observed `(issuer_id, sampling_stratum, era, representation_class, length_category)` cell, select the candidate with the smallest SHA-256 rank of the frozen seed, document ID, and page number. The resulting sample size is derived from the frozen corpus. Unobserved cells remain unavailable; pages are never invented or duplicated.

Primary-stratum priority is frozen in `sampling_spec.json`, rare recovery conditions first and native controls last. All engines are evaluated on every finalized Track-A unit, enabling paired page comparisons. HOLDOUT units may be predeclared and integrity-checked but not inspected for tuning.

The setup manifest initially carries `input_image_hash: NOT_YET_RENDERED`. A later execution worktree must render once, freeze the real 64-character image hash, and pass the identical file/hash to all four engines before any invocation. The setup worktree cannot execute that transition.

## Gold data

PageGold and DocumentGold are separate schema definitions.

PageGold may contain exact transcription, word/line references, heading text/level/localization, reading-order pairs, factual fields, and feasible layout regions. Factual fields preserve value, currency, unit, period, entity, page, box, and annotation status. DocumentGold contains `document_id`, `mda_present`, `mda_start_page`, `mda_end_page`, `start_heading`, `start_level`, `boundary_ambiguity`, excluded neighboring sections, and annotation provenance.

Missing annotation is `NOT_YET_ANNOTATED`. Model output, benchmark output, runtime telemetry, and reviewer expectations are separate data classes and never become gold automatically.

## Common output adaptation and raw provenance

Raw engine output is immutable and stored separately. Each future document×page×engine record includes image hash, exact engine version, configuration hash, runtime environment, raw output/hash, adapter output/version, status, telemetry, and failure details.

The common representation contains, for each unit, page, block ID, line ID, text, bounding box, block type, reading order, confidence, and source engine. Only values actually present in engine output may be copied. Missing box, confidence, reading order, identifier, or block type is `NOT_AVAILABLE`. The adapter rejects malformed boxes, out-of-range confidence, invalid order, source-engine mismatch, and page mismatch.

For cloud output, preserve provider/model/API version, request parameters, temperature, supported seed, region, request timestamp in runtime telemetry, and response hash. If provider version pinning is impossible, that limitation is reported. Preserved cloud output is replayed, not regenerated.

## Track-A endpoints

Level A primary endpoint is CER. Secondary endpoints are WER, heading text recovery, number accuracy, money-value accuracy, currency/unit accuracy, percentage accuracy, date accuracy, and entity accuracy. Every metric reports its denominator; CER/WER do not substitute for financially important token accuracy.

Structure is reported separately. Text/line/block boxes, regions, layout labels, heading localization/level, reading order, and comparable table localization are scored only when the engine claims/provides that capability. `NOT_AVAILABLE` is excluded from capability-specific denominators and reported as coverage.

Level B structure primary is pairwise reading-order accuracy. Secondary measures are inversion rate, sequence agreement, column-switch errors, heading-order correctness, heading precision/recall/F1, heading-level accuracy, and heading-level macro-F1. Kendall-style agreement is supplementary only when meaningful. Engine-provided order and ARPipe standardized downstream order are separate analyses.

The full heading inventory is evaluated, not only MD&A headings. Efficiency includes milliseconds per page/document, headings per document, and false headings per document.

## Track-B common pipeline and endpoints

After recovery every engine uses the same frozen sequence:

`document profile → routing → recovery → standardized reading order → heading inventory → candidate generation → span resolution → verification → quality gate`.

Candidate recall is the proportion of documents with valid gold starts whose gold start survives generation. Recall@1/@3/@5, average/median/maximum candidates, false candidates, milliseconds per document, and candidates evaluated are reported. A missed gold candidate is a hard downstream failure.

Level C primary endpoint is page-span IoU. Secondary measures are MD&A present/absent accuracy, IoU@0.50/@0.75/@0.90, exact and ±1 start/end, boundary distances, overrun, underrun, verification accuracy, and quality-gate behavior. Quality-gate states are `ACCEPT`, `REVIEW`, and `REJECT`; report acceptance accuracy, review rate, false acceptance/rejection, documents reviewed, and pages/spans reviewed.

MD&A end boundaries are never scored from isolated Track-A pages.

## Routing and legacy-font experiments

Routing classes are `native_ok`, `legacy_font`, `broken_text`, `scanned`, and `vector_text`. Report accuracy, macro-F1, per-class precision/recall, confusion matrix, false-native/false-OCR/false-legacy rates, route rates, OCR-avoided rate, throughput, and diagnostic-tier reach percentages.

Legacy-font remediation is a separate REMAP lane, not OCR. It reports character/word accuracy, heading recovery, number/entity preservation, milliseconds per page, pages per second, RAM, and failure rate.

The routing ablation has two conditions: actual detector→actual route and human-verified oracle route→correct route. Everything after routing is identical. Routing contribution is the registered paired difference in document-level page-span IoU; it is not generalized into a causal claim.

Oracle labels are `NATIVE`, `LEGACY`, or `OCR` with document/page, annotator, confidence, and reason. The subset is selected from frozen FIT/VALIDATION units before engine outputs. A deterministic 25% hash slice is double-annotated. Disagreement or low confidence triggers a third human adjudicator blind to all engine outputs; original annotations remain preserved.

## Uncertainty and paired comparisons

All intervals are two-sided 95% percentile intervals from 10,000 pre-seeded paired cluster-bootstrap replicates. Track-A analyses resample documents within declared split/stratum; Track-B analyses resample issuers. All paired engine observations from a sampled cluster remain together. Fewer than two clusters yields `NOT_ESTIMABLE` plus descriptive results.

Every comparison reports metric A, metric B, A−B difference, 95% interval, paired unit count, and cluster count. Missingness is reported by engine/metric; paired estimates use only units with both observations and state that denominator. Intervals are pointwise, with no family-wise significance claim. The method cannot change after results are seen.

## Efficiency, reliability, and cost

Quality, efficiency, and reliability remain separate. OCR telemetry records cold start, model load, warm runtime, wall time, seconds/page, pages/second, CPU/GPU seconds, peak RAM/VRAM, failure, timeout, and empty output. Cold start is never merged with steady state.

Cloud telemetry additionally records API latency, requests/retries, rate limits, actual usage/cost, cost/page, and cost/document. No vendor price is hard-coded into results.

The incremental-cost comparison is registered as: native-only baseline; actual native+remap+routed-OCR pipeline; OCR-all-pages baseline. Report total time/compute, OCR pages/rate/avoided rate, remap pages, and cost per successfully recovered page. These are measured engineering differences, not broader causal savings claims.

Track-B efficiency reports seconds/document/page, documents/hour, pages/hour, CPU/RAM/GPU/VRAM. Local results use measured compute; cloud results use actual usage records.

## Failure attribution

Failures retain stage and type: `INPUT_FAILURE`, `ENGINE_LOAD_FAILURE`, `MODEL_LOAD_FAILURE`, `TIMEOUT`, `API_ERROR`, `RATE_LIMIT`, `EMPTY_OUTPUT`, `MALFORMED_OUTPUT`, `OCR_GARBLED`, `READING_ORDER_FAILURE`, `HEADING_FAILURE`, `CANDIDATE_MISS`, `SPAN_BOUNDARY_FAILURE`, `VERIFIER_FALSE_ACCEPT`, and `VERIFIER_FALSE_REJECT`.

Future reports cross stage × failure type × document/stratum. `OCR_FAILURE` is not used when a more specific attribution is supported.

## Holdout and freeze procedure

FIT may support tuning; VALIDATION checks the frozen candidate method; HOLDOUT remains final-only. Before final freeze, HOLDOUT is allowed only for manifest predeclaration, schema validation, and split-integrity audit—never tuning, thresholds, engine selection, sampling changes, or error-driven methodology changes.

The configuration freeze consists of the JSON files under `configs/t0_4`, their SHA-256 manifest, the deterministic dual-track manifest, this protocol, and the P-X1 reuse audit. Setup is validated twice and compared byte-for-byte.

## Explicit non-execution boundary

This worktree may inspect repository metadata, build deterministic manifests, validate schemas/contracts, and run setup tests/audits. It must not execute Tesseract, PaddleOCR-VL, Surya, Gemini, AWS, or any OCR benchmark; acquire or render corpus PDFs; generate benchmark results; tune on outputs; change production ARPipe behavior; or modify frozen corpus/history.

Benchmark execution must occur only in a later, separately authorized worktree after T0.4 is committed and frozen.
