# T0.4 P-X1 reuse audit

Status: frozen before benchmark execution. T0.4 is an extension/refinement of P-X1, not P-X2. The P-X1 harness was inspected in the frozen Step-0A recovery snapshot; it is not present in the T0.3A-R1 Git tree and that historical snapshot is not modified.

## Component disposition

| P-X1 component | EXISTING | REUSE | NEW | DEPRECATED |
|---|---|---|---|---|
| Fixed page renderer | RGB PNG at 300 DPI with SHA-256 content addressing | Rendering contract and immutable image reuse | T0.4 renderer returns a repository-neutral image key and is never called during setup | Per-engine rendering or preprocessing |
| Strata classifier | Ten OCR-oriented categories, some overlapping | Condition vocabulary for scans, Hindi/Devanagari, legacy fonts, columns, tables, financial figures, and era | A single primary `sampling_stratum` plus multiple `condition_labels` with evidence levels | Treating overlapping conditions as mutually exclusive populations |
| Page selector | Seeded, round-robin page selection | Deterministic hashing and explicit shortfall behavior | Coverage-cell selection derives sample size from observed frozen metadata | Unjustified fixed target of 20 pages per stratum |
| Development/holdout splitter | Page manifests and an attempted document-level split | Explicit page uniqueness checks | Existing issuer-disjoint FIT/VALIDATION/HOLDOUT is preserved exactly | Splitting a document across development and holdout to satisfy quotas |
| Engine adapters | Tesseract, PaddleOCR-VL, Surya, Gemini, plus native extraction | Four named primary engines and independent failure recording | Registry separates capabilities and forbids silent substitution/fallback | Treating native PDF extraction as a fifth OCR engine |
| Runner | One rendered image is reused by engines | Same-image fairness principle and per-engine provenance | Image-only request gate; Track A cannot receive a PDF, neighbors, document text, TOC, bookmarks, metadata, or prior outputs | `page_context`, original-PDF access, and automatic native fallback in the primary comparison |
| Ground-truth interface | Page transcription and factual references | Page text/fact fields and `PENDING_REFERENCE` principle | Separate PageGold and DocumentGold; missing labels are `NOT_YET_ANNOTATED` | Inferring MD&A document boundaries from sampled pages |
| Text metrics | CER, WER, heading and factual recovery | CER/WER normalization and separate fact metrics | Explicit denominators and financially important token classes | Any aggregate winner score |
| Reading-order metric | Landmark rank agreement described as Kendall-style | Ordered anchors/pairs as annotation material | Pairwise order accuracy is primary; inversion rate and sequence/column/heading errors are secondary | Mandatory Kendall-style primary metric |
| Reporter | Engine × stratum × metric, no winner | Non-ranking reporting layout | Condition-label analyses, denominators, paired differences, clustered confidence intervals | Comparing engines over different page samples |
| Legacy-font lane | Native extraction was automatically added on legacy pages | Need for a separate native-text comparison | A distinct REMAP evaluation with preservation and efficiency metrics | Calling legacy-font remediation OCR or mixing it into primary OCR scores |
| Provenance | Image hash, engine version, preprocessing version, output text | Immutable hashes and explicit engine status | Separate raw output, common adapter output, gold, telemetry, and configuration schemas | Timestamp/hostname/path-bearing deterministic artifacts |
| Failure handling | Available/not-configured/unavailable/failed/empty/timeout | Failures remain explicit rows | Stage-specific standardized taxonomy | Collapsing all errors into `OCR_FAILURE` |

## Registered conflicts and changes

### Fixed 20-page quotas

- **OLD RULE:** Request 20 pages in each of ten strata, then report shortfalls.
- **CONFLICT:** The number was not justified; conditions overlap; quota balancing permitted document leakage across development and holdout.
- **PROPOSED CHANGE:** Select the minimum-hash page in every observed `(issuer_id, sampling_stratum, era, representation_class, length_category)` cell while preserving the frozen issuer split.
- **RATIONALE:** Sample size is a deterministic consequence of frozen coverage, not an arbitrary number or a result-informed choice.
- **SCIENTIFIC IMPACT:** Better corpus coverage and strict independence, with variable per-stratum counts reported explicitly.

### Document-overlap exceptions

- **OLD RULE:** Split a document between development and holdout when necessary to meet a stratum quota.
- **CONFLICT:** ARPipe's frozen partitions are issuer-disjoint and HOLDOUT is protected.
- **PROPOSED CHANGE:** Never move or split an issuer/document across FIT, VALIDATION, and HOLDOUT.
- **RATIONALE:** Partition integrity is more important than a page quota.
- **SCIENTIFIC IMPACT:** Paired engine estimates retain honest held-out evaluation; sparse cells may be descriptive or `NOT_ESTIMABLE`.

### Native PDF as an engine

- **OLD RULE:** Automatically add `native_pdf` on legacy-font pages.
- **CONFLICT:** The primary comparison requires identical image evidence and legacy remediation is REMAP, not OCR.
- **PROPOSED CHANGE:** Keep remapping/native extraction in a separate legacy-font experiment.
- **RATIONALE:** Native PDF bytes are a different modality.
- **SCIENTIFIC IMPACT:** Track-A engine effects are not confounded by input modality.

### Page context and document anchoring

- **OLD RULE:** Engine adapters could receive `page_context`; earlier ARPipe guidance recommended PDF partial-text anchoring for VLMs.
- **CONFLICT:** T0.4 primary Track A prohibits hidden PDF text, neighboring pages, document context, and external metadata.
- **PROPOSED CHANGE:** The Track-A interface accepts only one immutable PNG, its hash, and non-semantic unit identifiers.
- **RATIONALE:** All four engines must see the same visual evidence.
- **SCIENTIFIC IMPACT:** The primary comparison measures recovery method. Any context/native-PDF experiment must be a separately named future track.

### Reading-order primary

- **OLD RULE:** P-X1 treated landmark/Kendall-style rank agreement as the reading-order metric.
- **CONFLICT:** Rank correlation is not always meaningful with missing, duplicated, or region-level units.
- **PROPOSED CHANGE:** Pairwise order accuracy is primary; Kendall-style agreement is supplementary only when the reference supports it.
- **RATIONALE:** Pairwise judgments have a clear denominator and failure interpretation.
- **SCIENTIFIC IMPACT:** Reading-order results become more comparable without discarding supplementary rank analysis.

### Timestamped run products

- **OLD RULE:** P-X1 run directories and manifests included current timestamps and Git state.
- **CONFLICT:** T0.4 deterministic setup artifacts must reproduce byte-for-byte and contain no timestamp, hostname, UUID, or absolute path.
- **PROPOSED CHANGE:** Setup artifacts contain only frozen source/config hashes and derived units. Runtime timestamps are permitted only in future telemetry.
- **RATIONALE:** Configuration freeze and runtime provenance have different reproducibility roles.
- **SCIENTIFIC IMPACT:** Setup drift is detectable independently of execution environment.

## Reuse conclusion

T0.4 reuses P-X1's renderer contract, engine set, factual evaluation concepts, explicit missing-reference behavior, and non-ranking report principle. It replaces only the parts that conflict with the frozen corpus architecture, dual benchmark units, input-modality fairness, holdout protection, and deterministic preregistration.
