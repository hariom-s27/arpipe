**Status:** RESEARCH_ONLY — not a Gold protocol, annotation manifest, or benchmark result.

## Purpose and search method

This research answers five questions: what a later Gold package must contain; which fields need independent human evidence; how agreement and ambiguity should be represented; what adjudication preserves rather than hides disagreement; and which local tooling path causes the fewest methodological compromises.

Search concepts were: `inter-coder agreement annotation adjudication`; `boundary similarity text segmentation`; `pre-annotation anchoring bias`; `bootstrap confidence interval Krippendorff alpha`; `SEBI LODR Regulation 34(2)(e) management discussion analysis`; and the official documentation for Label Studio, Prodigy, and doccano. Primary methodological papers, official regulation, and official tool documentation were preferred. The Firecrawl paper index was queried with four separate framings; direct pages/PDFs were then inspected for S01–S06 and S08–S11. Backward chaining was performed from S01/S02 to the foundational reliability and agreement literature; forward/similar-paper searching was attempted through the research index. It identified no direct, peer-reviewed Indian-annual-report boundary-annotation study suitable to settle ARPipe's physical page boundaries. That is an evidence gap, not evidence of non-existence.

Inclusion required a source to bear on annotation reliability, boundaries, bias, regulation, or a tool capability relevant to ARPipe. Domain-mismatched studies are explicitly classified as transferable or general evidence in the register. Vendor claims are not treated as independent validation, and the local POCs (S12–S13) are evidence only for their named version, synthetic fixtures, and conditions.

### PageGold: minimum necessary reference

The smallest defensible PageGold for the frozen CER endpoint is not a small transcription subset. It is one human reference text for every page included in the declared CER denominator, accompanied by an explicit `text_status` such as `VISIBLE_TEXT`, `NO_VISIBLE_TEXT`, `PARTLY_UNREADABLE`, or `TECHNICAL_RENDERING_AMBIGUITY`. An empty visible page must be represented as an empty reference, not silently omitted. This distinguishes an empty reference from a missing reference and permits a transparent zero-length denominator rule to be frozen before results.

Annotators should transcribe **what is visually presented**, preserving visible characters, punctuation, meaningful line breaks, script, symbols, and uncertainty markers. They should not consult hidden PDF text or an extraction output. A later protocol may derive a normalized evaluation string, but only mechanically from the separately preserved visible transcription under a predeclared rule. It must not ask annotators to improvise normalization after observing system errors. Tables, figures, decorative text, and unreadable characters need typed inclusion/exclusion and uncertainty rules before Gold creation.

Headings, typed factual fields, and reading-order anchors are justified only by their named secondary/structure metrics. A generic region layer is not justified by the frozen CER endpoint. If retained, every region must have a type and a consuming metric or audit purpose.

### Nested Gold conclusion

Nested Gold is valid only as a **declared metric-specific layer**. It cannot silently replace the frozen all-page CER denominator: a subset-only transcription layer would produce a subset CER, not the registered Track-A CER. A future integration may retain all-page transcription for CER while sampling factual or specialist heading diagnostics deterministically; it must publish each layer's population, seed, split/issuer counts, missingness, and confidence interval separately. Likewise, a reading-order or factual subset must never be used to describe all 475 pages without an explicit sampling claim. This is a methodological conclusion, not a change to T0.4.

## B7: reading-order unit and relation

The frozen common representation permits blocks, lines, boxes, and integer `reading_order`, but allows each to be `NOT_AVAILABLE`; `gold_schema.json` leaves `lines` and `regions` untyped. The repository contains a setup invariant for the primary pairwise metric, not an executable reading-order evaluator. Therefore no semantic reference unit is actually frozen.

The research recommendation is an **annotator-defined atomic visual text region**: the smallest contiguous visual unit that should move as one item in the intended reading sequence. It has an immutable `anchor_id`, page-local geometry, visible text, and typed role. This is usually a text block, may be a line when a block must be split to express order, and is never copied from an engine's block/line identifiers. Decorative furniture, page numbers, pure rules, and excluded table material receive an explicit exclusion reason rather than an invented place in an order. A table can be represented either as one `TABLE_REGION` excluded from prose order or as a predeclared row/cell scheme; the selected convention must be frozen before annotation.

The proposed relation is an ordered directed pair `(anchor_i, anchor_j)` meaning `anchor_i PRECEDES anchor_j`. Eligible pairs are all unordered pairs among common, non-tied, non-excluded anchors on the same page; pairwise accuracy is then interpretable as the share whose direction agrees. Adjacent-only pairs are retained only as a diagnostic because they can conceal non-adjacent column inversions. Ties, duplicate anchor text, overlap, absent anchors, and cross-page relationships are explicit statuses, not guessed order. A total sequence and Kendall-style statistic can be supplementary only for pages whose anchors form a complete, non-tied order. This is **RECOMMENDED_PENDING_AUTHOR_APPROVAL**, because the downstream evaluator must be implemented against the same anchor identity contract before protocol freeze.

## Context, aids, and leakage

| Target | Minimum context | May be shown | Must not be shown during independent work | Reason |
|---|---|---|---|---|
| Page transcription, typed headings, page-local order, page facts | target rendered page only | image zoom and non-semantic task ID | hidden PDF text, OCR/model output, another label, TOC/bookmark, neighbour pages | aligns human evidence with Track-A visual input and prevents anchoring (S06–S07) |
| DocumentGold presence/span | whole report with physical page navigation | page thumbnails, document-local TOC/bookmarks as marked discovery aids | system candidates, OCR/pipeline output, benchmark split/condition labels, another annotator's record | boundaries depend on actual report structure, not only a page |
| OracleRouteGold | rendered page plus written route protocol | only frozen allowed evidence | all engine outputs and route effects | already frozen in `oracle_routing_spec.json` |

TOC, bookmarks, and PDF metadata are `ANNOTATION_AID`, not Gold. For DocumentGold, an annotator may use them to locate candidates but must ground the record in visible report structure and record a `source_aid_used` flag. For Track A, those aids are prohibited. Visually unavoidable features—scan quality, layout, language, or document length—are `UNAVOIDABLE_SOURCE_INFORMATION`; filenames, issuer names, directory paths, split names, sampling strata, engine labels, and task titles are preventable leakage and must be removed from the annotation interface.

## Provenance and package design

Each future action record should contain: opaque task/document ID; physical page index (zero-based in data, one-based only in UI); source-PDF SHA-256; rendered-image SHA-256 where applicable; anonymous annotator ID; protocol version; tool and version; UTC timestamp; annotation/double-annotation/adjudication/ambiguity status; and append-only raw payload lineage. DocumentGold additionally needs source-aid use, candidate span IDs, chosen/admissible spans, start heading, neighbour sections, and reason codes. PageGold additionally needs anchor IDs, coordinate convention, and text/fact normalization version. Raw independent records and adjudicated reference records must be distinct immutable objects.

The package should expose a single page per Track-A task. A Track-B task should expose the whole report with jump-to-page and visible physical index, while limiting accidental metadata leakage. The adjudicator alone receives the linked raw records after independent work closes. This document does not create a final schema or a task manifest.
